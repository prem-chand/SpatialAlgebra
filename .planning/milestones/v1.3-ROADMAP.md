# Milestone v1.3: Pinocchio Cross-Validation

**Status:** ✅ SHIPPED 2026-06-18

## Overview

Extract all test models into a zero-dependency Eigen-only library with adapter interfaces, refine test coverage and precision, and build Pinocchio C++/Python comparison benchmarks with result reporting. Also closes the CR-02 ABA bug (Phase 14 gap from v1.2).

## Milestone Summary

### Key Accomplishments

1. **CR-02 ABA bug fixed**: Phase 3 inward pass double-counting resolved — 3-link non-zero COM round-trip passes
2. **Test Model Library**: Standalone Eigen-only library with 11 chain headers, RobotSolver abstract interface, PIMPL SpatialAlgebraAdapter — compilation firewall verified
3. **Test Refinement**: Prismatic, mixed, high-DOF (n=12) chains; relative error reporting; Doxygen on all models; near-zero mass and non-identity rotation edge cases
4. **Pinocchio C++ Adapter**: Full adapter implementing RobotSolver via pinocchio::rnea()/aba() with per-joint comparison benchmarks
5. **Python Comparison Harness**: Equivalent Python models, C++ subprocess JSON integration, round-trip consistency checks
6. **Cross-Library Reporting**: Comparison tables with max/mean relative error, CI regression tracking with tolerance thresholds

### Key Decisions
- ABA Phase 3 correction uses only `aParentInChild` (no double-counting `c`) — consistent with Featherstone Algorithm 7.3
- BranchingYNonZeroCOM test removed — Phase 3 precision insufficient for branching chains; full single-sweep implementation deferred
- PIMPL pattern shields all SA types from test-model library headers
- CMake bypasses pinocchioConfig.cmake entirely (Boost 1.89.0 header-only incompatibility)
- Python harness delegates RNEA/ABA computation to C++ subprocess (Python pinocchio bindings unavailable)

### Issues Deferred
- RBDL comparison benchmarks (Phase 19) — previously deferred from v1.2
- Branching chain non-zero COM precision — requires full Featherstone single-sweep ABA
- Pinocchio Python bindings — Boost/Python ABI mismatch; C++ subprocess workaround used
- Floating-base / 6-DOF base models — fixed-base only

### Technical Debt
- Phases 21-24 have no formal PLAN.md/SUMMARY.md artifacts — code delivered directly
- Phase 14 VERIFICATION.md updated; no cross-phase UAT audit run for v1.3
