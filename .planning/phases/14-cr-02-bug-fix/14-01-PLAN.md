<objective>
Restructure the ABA inward pass to include the missing articulation (condensation) step per Featherstone Algorithm 7.3, then update and expand multi-link verification tests.

**Purpose:** Fix forward dynamics for chains with 3+ joints. Currently, `inwardPass()` accumulates child inertias but never condenses (removes the joint motion subspace DOF) before passing to the parent. The parent overestimates reflected inertia, causing all multi-link round-trip consistency tests to fail.

**Output:** Corrected `inwardPass()` with inline condensation math, and test suite with verified multi-link dynamics (3 tests go from FAIL→PASS, 2 new tests validate condensation physics).
</objective>

<task type="auto">
  <name>Task 1: Restructure inwardPass() — single sweep with condensation</name>
  <files>src/ForwardDynamics.cpp</files>
  <action>
    Replace the current `inwardPass()` method (lines 53-126) with a restructured version.

    **Keep Phase 1 unchanged** (lines 56-73): Initialize `Ia` and `pa` from rigid body inertia for all links. This loop is correct — no changes.

    **Replace Phase 2 + Phase 3** (lines 75-125) with a single tip-to-base sweep. Each link does:

    1. **Accumulate** — Child contributions were already added by previous iterations (when children condensed and passed to parent). This is a no-op in code — it's a structural change: instead of a separate Phase 2 that bulk-transfers all Ia/pa, each child individually adds its condensed Ia/pa to the parent immediately after solving and condensing.

    2. **Solve for qddot** — Same math as current Phase 3, but using the free-function `dot`:
       ```
       MotionVector IaS = links[i].Ia.apply(links[i].S);
       double D = dot(links[i].S, IaS);                    // free function from SpatialUtils.h:65
       double u = tau[i] - dot(links[i].S, links[i].pa);   // S^T * pa via free function
       // EPSILON guard (same as current, ~1e-10)
       links[i].qddot = u / D;
       ```

    3. **Condense (if parent != -1)** — Per D-01, D-03. Skip for base link. Remove joint DOF from Ia and pa before passing to parent:
       ```
       double invD = 1.0 / D;
       
       // Outer product blocks from ForceVector IaS
       Vector3d t = IaS.getAngular();
       Vector3d f = IaS.getLinear();
       
       // Ia' = Ia - (Ia*S)*(1/D)*(Ia*S)^T
       lt inertiaCorr = lt::fromFullMatrix(t * t.transpose()) * invD;
       Eigen::Matrix3d HCorr = t * f.transpose() * invD;
       lt massCorr = lt::fromFullMatrix(f * f.transpose()) * invD;
       
       links[i].Ia = links[i].Ia + (ArticulatedBodyInertia(inertiaCorr, HCorr, massCorr) * (-1.0));
       
       // pa' = pa + Ia*S * qdd
       links[i].pa = links[i].pa + (IaS * links[i].qddot);  // ForceVector * double → ForceVector
       ```

    4. **Pass to parent** — Transform condensed Ia/pa to parent frame. Same transform methods as current Phase 2:
       ```
       ArticulatedBodyInertia IaTransformed = links[i].X.invtformABI(links[i].Ia);
       links[parent].Ia = links[parent].Ia + IaTransformed;
       
       ForceVector paTransformed = links[i].X.inverseTransformForce(links[i].pa);
       links[parent].pa = ForceVector(
           links[parent].pa.getAngular() + paTransformed.getAngular(),
           links[parent].pa.getLinear() + paTransformed.getLinear()
       );
       ```

    **Critical ordering (per D-02):**
    - Solve qddot BEFORE condensing (condensation depends on qddot for the `pa' = pa + Ia*S*qdd` term)
    - Condense BEFORE passing to parent (the bug was passing uncondensed Ia)
    - Initialize Ia/pa for ALL links in Phase 1 before the sweep (not during the sweep)

    **What NOT to change:**
    - Do NOT add any new includes — all needed headers (`SpatialUtils.h`, `ArticulatedBodyInertia.h`, `LowerTriangular.h`, `PluckerTransform.h`) are already transitively included by `ForwardDynamics.h`
    - Do NOT modify `computeAccelerations()` (lines 128-160) or `outwardPass()` (lines 19-51)
    - Do NOT touch any `include/` files per D-07
    - Do NOT use general matrix inversion — `1/D` is correct for 1-DOF joints (scalar D)

    **After implementation,** remove the `using Vector3d = ...` type alias at line 47? No, `Vector3d` is already defined in `SpatialVector.h` as `Eigen::Matrix<double, 3, 1>`. It's available throughout the `SpatialAlgebra` namespace. Use it directly — no typedef needed in the .cpp file.

    **Added include note:** The `using` declarations for `ForceVector` and `MotionVector` are from their respective headers which ForwardDynamics.h already includes. The `lt` type alias is from `SpatialVector.h` which `ForwardDynamics.h` includes. All required types are in scope.
