## Current State

**Phase 14-01 (completed 2026-06-04):** Fixed cross product formulas in `SpatialUtils.h` — `cross(MotionVector, ForceVector)` and `cross(ForceVector, ForceVector)`. All 11 test executables pass.

**Remaining bug (discovered Phase 18, 2026-06-06):** The 3-phase inward pass still has the condensation ordering bug. It computes partial qddot assuming zero parent acceleration, then corrects in a separate Phase 3. This correction algebraically over-corrects for non-zero COM because `S^T * Ia_unc * c` is already included in `pa` (initialized as `Ia*c + cross(v, Ia*v) + f`). With zero COM, skew(com)*mass = 0, making the inertia block-diagonal, and the correction bug path is not triggered.

**Current inwardPass() structure** (src/ForwardDynamics.cpp:82-179):
- Phase 1 (lines 84-102): Initialize Ia/pa from RBI — CORRECT, KEEP
- Phase 2 (lines 104-158): Tip-to-base sweep — partial qddot, condense, pass to parent
- Phase 3 (lines 160-179): Base-to-tip — correct qddot with Ia_unc*a_prime, compute a[i]

## Target State

Single tip-to-base sweep per Featherstone Algorithm 7.3. For each link (tip→base):
1. Accumulate — children already added from prior iterations
2. Solve qddot — FINAL value: `u/D` where `u = tau[i] - dot(S, pa)`, `D = dot(S, Ia.apply(S))`
3. Condense — `Ia' = Ia - (Ia*S)*(1/D)*(Ia*S)^T`, `pa' = pa + Ia*S*qdd`
4. Pass to parent — transformInertiaToParent + inverseTransformForce

Then forward pass: `a[i] = X*a_parent + c[i] + S[i]*qddot[i]` (no correction).
