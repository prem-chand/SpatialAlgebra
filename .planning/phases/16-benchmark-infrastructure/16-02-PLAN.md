    Write benchmarks/common/model_factory.cpp.

    Implementation patterns (from examples/dynamics.cpp lines 37-101 and RESEARCH.md Common Operation 1):

    1. File includes: `#include "model_factory.h"`, `#include "PluckerTransform.h"`, `#include "RigidBodyInertia.h"`, `#include "LowerTriangular.h"`
    
    2. namespace SpatialAlgebra::Bench { ... }
    
    3. createFD(int nDOF, const JointConfig& cfg):
       - ForwardDynamics fd;
       - fd.links.reserve(nDOF);
       - For i = 0..nDOF-1:
         - ForwardDynamics::Link link;
         - link.parent = i - 1;  // -1 for base (index 0), i-1 for children
         - link.X = PluckerTransform(Rotation(Eigen::Matrix3d::Identity()), cfg.translation);
           (Identity rotation + configurable translation — per D-02, joint axis is separate)
         - link.I = RigidBodyInertia(cfg.mass, cfg.com, lt::Identity(3));
           (Diagonal unit inertia with configurable mass and COM — per D-04)
         - link.S = cfg.axis;  (Configurable joint axis — per D-02)
         - link.q = 0.0; link.qdot = 0.0;
           (State initialized to zero; benchmark code applies random state via RandomState)
         - link.f = ForceVector(Eigen::Vector3d::Zero(), Eigen::Vector3d::Zero());
           (External forces initialized to zero)
         - fd.links.push_back(std::move(link));
       - return fd;
    
    4. createID(int nDOF, const JointConfig& cfg):
       - Same loop structure, but constructs InverseDynamicsLink instead of ForwardDynamics::Link.
       - InverseDynamicsLink has fields: parent, X, I, S, q, qdot, qddot, v, a.
       - No Ia, pa, f, c fields (those are ForwardDynamics-specific).
       - link.qddot = 0.0 (initialized; benchmark sets it).
       - Return InverseDynamics.
    
    5. createFD(const std::vector<JointConfig>& configs):
       - Per-link overload (D-04): each link gets its own JointConfig.
       - configs.size() determines nDOF.
       - Same loop as createFD but with cfg = configs[i].
    
    6. createID(const std::vector<JointConfig>& configs):
       - Same pattern for InverseDynamics with per-link configs.
    
    7. createFDBranching / createIDBranching:
       - Create serial chain of nDOF links where link at index `branchPoint` has two children:
         one at branchPoint+1 (continues main branch), one at branchPoint+2 (side branch).
       - The side branch link also has parent = branchPoint.
       - After branching, subsequent indices continue on the main branch.
       - All subsequent children of the side branch link follow normally.
       - This is a Y-shaped chain with one split point.
       - Implementation: create serial chain normally, then for the side branch link,
         add it with parent=branchPoint after the main branch link at branchPoint+1.
       - Note: The branchPoint must be within [0, nDOF-3] to leave room for at least
         one link on each branch after the split.
    
    Use `using` aliases from the project conventions where convenient (e.g., `using lt = LowerTriangular;` inside the .cpp file).
