    **Test 1 — Hand-derived 1-link ABA (external oracle)**
    
    For a single pendulum with unit inertia about Z, torque tau=1.0:
    - Expected: qddot = 1.0 rad/s² (hand-derived: I·q̈ = τ → 1·q̈ = 1 → q̈ = 1)
    - This is the simplest independent oracle: Newton's second law.
    
    ```cpp
    /**
     * @brief Single-link ABA with hand-derived expected value
     * @details qddot = tau / I = 1.0 / 1.0 = 1.0 rad/s²  (hand-derived external oracle — not from the library)
     * @see D-19: External oracle for validation (known-answer test)
     */
    TEST(ForwardDynamicsTest, SingleLinkHandDerivedOracle) {
        ForwardDynamics fd;
        Link link;
        link.parent = -1;
        link.X = PluckerTransform(Rotation(Eigen::Matrix3d::Identity()), Vector3d::Zero());
        link.I = RigidBodyInertia(1.0, Vector3d::Zero(), lt::Identity(3));
        link.S = MotionVector(Vector3d(0, 0, 1), Vector3d::Zero());
        link.q = 0.0; link.qdot = 0.0;
        link.f = ForceVector(Vector3d::Zero(), Vector3d::Zero());
    ```

    **Test 2 — Three-link serial chain with structural invariants (CR-02 regression test)**
    
    Three identical links, Z-axis revolute joints, transforms along X:
    - With CR-02 unfixed, qddot values are (0.333, 0.25, 0.25) — middle and tip identical (bug)
    - With CR-02 fixed, expected hierarchy: qddot[0] < qddot[1] < qddot[2] (more inertias at base → slower)
    - Still useful as a regression test to document the bug
    
    ```cpp
    /**
     * @brief Three-link ABA with structural invariants
     * @details Three identical Z-axis revolute links offset along X.
     *          CR-02 bug causes middle==tip acceleration. Once fixed, hierarchy is base < middle < tip.
     * @see CR-02: ABA inward pass overwrites child inertias during Phase 2 accumulation
     */
    TEST(ForwardDynamicsTest, ThreeLinkSerialChain) {
        ForwardDynamics fd;
        
        auto addLink = [&](int parent, const Vector3d& pos) {
            Link l;
            l.parent = parent;
            l.X = PluckerTransform(Rotation(Eigen::Matrix3d::Identity()), pos);
            l.I = RigidBodyInertia(1.0, Vector3d::Zero(), lt::Identity(3));
            l.S = MotionVector(Vector3d(0, 0, 1), Vector3d::Zero());
            l.q = 0.0; l.qdot = 0.0;
            l.f = ForceVector(Vector3d::Zero(), Vector3d::Zero());
            fd.links.push_back(l);
        };
        
        addLink(-1, Vector3d::Zero());  // base
        addLink(0, Vector3d(1, 0, 0));   // middle
        addLink(1, Vector3d(1, 0, 0));   // tip
        
        Eigen::VectorXd tau(3);
        tau << 1.0, 0.5, 0.25;
        fd.computeAccelerations(tau);
        
        // All accelerations positive and finite
        for (int i = 0; i < 3; i++) {
            EXPECT_GT(fd.links[i].qddot, 0.0) << "Link " << i << " acceleration should be positive";
            EXPECT_TRUE(std::isfinite(fd.links[i].qddot)) << "Link " << i << " acceleration should be finite";
        }
        // Structural coupling: all three accelerations should differ (multi-link inertia coupling)
        // When CR-02 is fixed: qddot[0] < qddot[1] < qddot[2]
        // Currently (CR-02 unfixed): qddot[0] ≈ 0.333, qddot[1] ≈ 0.25, qddot[2] ≈ 0.25
        EXPECT_NE(fd.links[0].qddot, fd.links[1].qddot);
        // CR-02 causes qddot[1] == qddot[2] — this assertion documents the bug
        // Once CR-02 is fixed, change to: EXPECT_NE(fd.links[1].qddot, fd.links[2].qddot);
    }
    ```
