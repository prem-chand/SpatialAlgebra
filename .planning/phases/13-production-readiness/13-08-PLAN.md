    ### Gravity Support

    Both `computeAccelerations()` (ABA) and `computeTorques()` (RNEA) accept an optional
    `gravity` parameter (default: `Vector3d::Zero()` for no gravity):

    ```cpp
    // ABA with Earth gravity (Z-up convention):
    SpatialAlgebra::ForwardDynamics fd;
    // ... set up links ...
    fd.computeAccelerations(tau, Vector3d(0, 0, -9.81));

    // RNEA with Earth gravity:
    SpatialAlgebra::InverseDynamics id;
    // ... set up links ...
    Eigen::VectorXd tau = id.computeTorques(qddot, Vector3d(0, 0, -9.81));
    ```

    The gravity vector is expressed in world/base coordinates and is propagated through
    the base link's bias acceleration per Featherstone's formulation. See
    [`MATHEMATICAL_CONVENTIONS.md`](MATHEMATICAL_CONVENTIONS.md) for details.
    ```

      an optional `gravity` parameter defaulting to zero (backward compatible).
    - **Removed methods**: `MotionVector::crossForce()` and `ForceVector::crossMotion()` removed.

    - **GTest fallback**: Library builds without system-installed GTest via CMake FetchContent.
    ```

    // Set up a single-link pendulum
    ForwardDynamics fd;
    Link link;
    link.parent = -1;  // Base link
    link.X = PluckerTransform(Rotation::Identity(), Vector3d::Zero());
    link.I = RigidBodyInertia(1.0, Vector3d::Zero(), lt::Identity(3));
    link.S = MotionVector(Vector3d(0, 0, 1), Vector3d::Zero());  // Z-axis joint
    link.q = 0.0; link.qdot = 0.0;
    fd.links.push_back(link);

    // Compute accelerations from torques
    Eigen::VectorXd tau(1);

    fd.computeAccelerations(tau);

    std::cout << "Joint acceleration: " << fd.links[0].qddot << " rad/s²" << std::endl;
    ```
