    Create MATHEMATICAL_CONVENTIONS.md at repository root documenting:
    1. Coordinate frame convention: right-handed Cartesian. Gravity vector g is gravitational acceleration in world coordinates (e.g., [0,0,-9.81] on Earth).
    2. Spatial vector representation: s = [angular; linear].
    3. Cross-product formulas (Featherstone Ch 2), all four combinations, with force x force as canonical single-source:
       - motion x motion: angular = w1xw2, linear = w1xv2 - w2xv1 + v1xw2
       - motion x force: angular = w1xt2 + v1xf2, linear = w1xf2
       - force x motion: angular = t1xw2 + f1xv2, linear = t1xv2 + f1xw2
       - force x force (D-02): angular = t1xt2 + f1xf2, linear = t1xf2 - t2xf1
    4. Gravity convention (D-07, D-08):
       - ABA: base link bias acceleration c0 = -g. Default Vector3d::Zero().
       - RNEA: base acceleration a0 = S.qddot - [0; g].
       - Propagates through recursive acceleration chain.
    5. Plucker transform conventions: X.transformMotion(v) transforms parent-to-child. Force transforms use X.transformForce(f) = X^{-T} * f_parent. Inward pass uses X.invtformABI(Ia).
    6. Tolerance strategy: EPSILON=1e-10 for unit tests (direct algebraic operations), EPSILON=1e-8 for multi-step dynamics round-trips (accumulated FP error).
    7. API change log documenting: crossForce/crossMotion removals (D-04), Vector3d in namespace (D-23), SpatialAlgebra.h umbrella header (D-28).

    File must have heading "# SpatialAlgebra: Mathematical Conventions" and "## Change Log" section. At least 80 lines.
